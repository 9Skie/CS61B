Dijkstra's algorithm is a single source shortest path algorithm for graphs with non-negative edge weights.

We will look at 2 implementations of this algorithm.


Suppose that we are in a city A, and there are other cities like B, C, D... etc, and we want to find the shortest path from A to another city, any other city.

![[Screenshot 2026-11-09 at 7.17.29 PM.jpg|500]]

The idea behind how we do this, is start at A, as that's the initial city which we are coming from, and we ask 'what is the distance from A to A'? It is 0, so we label it 0.

![[Screenshot 2026-11-09 at 7.18.43 PM.jpg|500]]


Then, we take a look at where A could get to, it could get to C in 3 (time units), ad F in 2, and so it updates it's estimates to those nodes as 3 and 2 respectively.

![[Screenshot 2026-11-09 at 7.19.49 PM.jpg|500]]

Now, we consider A as fully explored, in the sense that we have updated all the estimates of distance of A to the nodes that it can reach.

Now, we will go to the next node to explore it and update the estimate of it's distance from A from the node's connections.

So, which node do we pick? We pick the node with the smallest estimated distance so far, in this case, F.

![[Screenshot 2026-11-09 at 7.21.44 PM.jpg|500]]


After using routes through F to update the distance estimates from A to each of F’s neighbors, we consider F explored. We can now say for sure that the shortest distance from A to F is 2.

How did we get those estimates? For each node directly connected to F, we break the route into two parts.
1. Start with the known distance from A to F.
2. Add the distance from F to that node. If the total is smaller than our current estimate from A, update the estimate.

Then we repeat the process with the next unexplored node.


![[Screenshot 2026-11-09 at 7.37.36 PM.jpg|500]]

So from F, we were able to updates out estimates to E, B, and G.
- Our estimates to C have not been updated, as the original estimate distance from A to C is 3, which if we estimate going from A to F to C, would be a distance of 5, so we retain the 3. 

We repeat and pick C, as now it has the smallest estimate of distance, 3, from A.

![[Screenshot 2026-11-09 at 7.39.40 PM.jpg|500]]


This process repeats updating the estimated distance of A to every other node, until we consider all nodes on the graph as visited.

But say, we just cared about the actual shortest path between A and B, through our algorithm, we have realized the shortest distance between A and B is 6, but that is distance, not a path, how can we use this value to trace out the shortest path between A and B?

![[Screenshot 2026-11-09 at 7.42.35 PM.jpg|500]]


Well, that means giving an extra step for our algorithm, at every time we update our estimate for a town, we should also keep track of the previous town we visited in order to get to this estimate.

If we keep track of that for each of the towns as we progressed through the algorithm, then we can unroll this question back and back until we get to the beginning, A.

![[Screenshot 2026-11-09 at 8.10.36 PM.jpg|500]]

Now, the above is very conceptual, we will look at a more concrete implementation of it now, assuming our beginning node is called $s$

- We need to maintain a distance array, which contains the estimates for the distance of all nodes to $s$, by default, they are all set to infinity. 
- Keep a priority queue of `(node, estimated distance from s)` pairs so we can pick the unexplored node with the smallest distance estimate.
- Begin by inserting `(s, 0)` into the priority queue
- For each outgoing edge, check whether going through the current node gives a shorter route from `s` to the neighbor. If so, update the estimate and push `(neighbor, new distance)` into the priority queue.

![[Screenshot 2026-11-09 at 8.38.22 PM.jpg|500]]

By default, we assign `0` to the distance of the starting node to itself, and insert a `(0, 0)` into the priority queue for the program to start.


From node 0, we can visit 2 nodes, node 1 and node 2, with distance 4 and 1 respectively.

![[Screenshot 2026-11-09 at 8.40.57 PM.jpg|500]]


Then, as we see from the priority queue, we take out the node with the smallest distance value to $s$ from it.

![[Screenshot 2026-11-09 at 8.42.59 PM.jpg|500]]


This is how it looks like after we are done updating node 1 and node 3's estimated best distance from node 2.

![[Screenshot 2026-11-09 at 8.42.44 PM.jpg|500]]


The next node with the shortest estimated distance is node 1, and from it we can update the estimated shortest distance from node 3 to node 1.

Now, we can look at the queue and realize there's a previously saved estimated shortest distance of node 1 to node 0, but if we compare it's current saved estimated shortest distance and it's previously saved shortest distance, it's shorter, we have found already a better estimate, and so we can ignore this in the priority queue.

## Pseudocode 

This would be it's pseudo code for execution.

```python
# Runs Dijkstra’s algorithm and returns an array that contains
# the shortest distance to every node from the start node s.
# g - adjacency list of weighted graph
# n - the number of nodes in the graph
# s - the index of the starting node (0 ≤ s < n)
function dijkstra(g, n, s):
    vis = [false, false, ..., false]  # size n
    dist = [∞, ∞, ..., ∞]             # size n
    dist[s] = 0

    pq = empty priority queue
    pq.insert((s, 0))

    while pq.size() != 0:
        index, minValue = pq.poll()
        vis[index] = true

        for (edge : g[index]):
            if vis[edge.to]: continue

            newDist = dist[index] + edge.cost
            if newDist < dist[edge.to]:
                dist[edge.to] = newDist
                pq.insert((edge.to, newDist))

    return dist
```

## Problem?

This doesn't help us find shortest paths, after you looked through the pseudo code, it only tells us about shortest distances.

To recover the path itself, we also keep a predecessor array `prev`, where `prev[i]` stores the node we came from on the best route to `i` so far.
- Whenever we find a shorter route to `i`, we update both `dist[i]` and `prev[i]`. 

To recover the path to a reachable node, start at that node, follow `prev`'s indexes one after another back to `s`, and reverse the resulting list.

This is the edited pseudocode:

```python
# Runs Dijkstra’s algorithm and returns the shortest distance
# from s to every node and the prev array for reconstructing paths.
# g - adjacency list of the weighted graph
# n - the number of nodes in the graph
# s - the index of the starting node (0 ≤ s < n)
function dijkstra(g, n, s):
    vis = [false, false, ..., false]  # size n
    prev = [null, null, ..., null]    # size n
    dist = [∞, ∞, ..., ∞]             # size n
    dist[s] = 0

    pq = empty priority queue
    pq.insert((s, 0))

    while pq.size() != 0:
        index, minValue = pq.poll()
        vis[index] = true
        if dist[index] < minValue: continue

        for (edge : g[index]):
            if vis[edge.to]: continue

            newDist = dist[index] + edge.cost
            if newDist < dist[edge.to]:
                prev[edge.to] = index
                dist[edge.to] = newDist
                pq.insert((edge.to, newDist))

    return (dist, prev)
```

To actually find the shortest path, we will utilize this `prev` and make this function.

```python
# Finds the shortest path between two nodes.
# g - adjacency list of the weighted graph
# n - the number of nodes in the graph
# s - the index of the starting node (0 ≤ s < n)
# e - the index of the end node (0 ≤ e < n)
function findShortestPath(g, n, s, e):
    dist, prev = dijkstra(g, n, s)
    path = []

    if (dist[e] == ∞) return path

    for (at = e; at != null; at = prev[at])
        path.add(at)

    path.reverse()
    return path
```

## The Eager Dijkstra


Our current implementation of Dijkstra is called 'lazy' because it inserts duplicate key value pairs into the priority queue, as it is more efficient to insert a new key value pair then to update the existing key's value.

However, this approach is inefficient for dense graphs, as we will end up with several very outdated key value pairs in the priority queue, the eager version solves this using an indexed priority queue.

It works still in practice very similar to lazy Dijkstras, just that we don't have duplicate pairs within the priority queue.

```python
function dijkstra(g, n, s):
    vis = [false, false, ..., false]  # size n
    prev = [null, null, ..., null]    # size n
    dist = [∞, ∞, ..., ∞]             # size n
    dist[s] = 0

    pq = empty indexed min priority queue
    pq.insert(s, 0)

    while pq.size() != 0:
        index, minValue = pq.poll()
        vis[index] = true

        for (edge : g[index]):
            if vis[edge.to]: continue

            newDist = minValue + edge.cost
            if newDist < dist[edge.to]:
                prev[edge.to] = index
                dist[edge.to] = newDist

                if pq.contains(edge.to):
                    pq.decreaseKey(edge.to, newDist)
                else:
                    pq.insert(edge.to, newDist)

    return (dist, prev)
```
