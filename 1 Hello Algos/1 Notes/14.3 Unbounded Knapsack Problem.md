So... it's still knapsack, but instead of just each item being a yes no choice in picking, we have the ability to have each item  be selected multiple times.

Boom! Now we are fucked, actually not really. We still make a “take it or skip it” decision. The change is that taking an item no longer removes it from consideration.

Let the current item be $i$, its weight be $w$, its value be $v$, and the remaining capacity be $c$.

- Skip it: move to $i-1,c$. We finish considering this item and move to the previous one.
- Take it: move to $i,c-w$ and gain value $v$. Capacity decreases, but $i$ stays the same because we can take another copy.

So the recurrence changes from:
- 0–1 knapsack: $dp[i,c]=\max(dp[i-1,c], v+dp[i-1,c-w])$
- Unbounded knapsack: $dp[i,c]=\max(dp[i-1,c], v+dp[i,c-w])$

Only the “take it” part changes from $i-1$ to $i$. For example, after taking a banana, we can take another banana if it still fits. If the item is too heavy, we must skip it.

Comparing the code for the two problems, there is one change in state transition from  to , with everything else identical:

```python
def unbounded_knapsack_tabulation(
    wgt: list[int], val: list[int], cap: int
) -> int:
    """Solve unbounded knapsack using bottom-up tabulation."""
    n = len(wgt)

    # Row 0: no items. Column 0: no capacity.
    dp = [[0] * (cap + 1) for _ in range(n + 1)]

    # Fill one row for each item.
    for i in range(1, n + 1):
        weight = wgt[i - 1]
        value = val[i - 1]

        # Fill capacities from small to large.
        for c in range(1, cap + 1):
            skip = dp[i - 1][c]

            if weight > c:
                # The item does not fit.
                dp[i][c] = skip
            else:
                # Stay in the same row so this item can be taken again.
                take = value + dp[i][c - weight]
                dp[i][c] = max(skip, take)

    return dp[n][cap]
```
