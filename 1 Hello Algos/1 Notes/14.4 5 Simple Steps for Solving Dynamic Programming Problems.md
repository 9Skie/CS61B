## Longest Increasing Subsequence (LIS)

Given a sequence $a_1, a_2, \ldots, a_n$, find the **length** of its longest strictly increasing subsequence.

You may skip elements, but the elements you keep must stay in their original order, and each one must be strictly larger than the previous one.

- For `[3, 1, 8, 2, 5]`, the answer is `3`. One longest increasing subsequence is `[1, 2, 5]`.
    
- For `[5, 2, 8, 6, 3, 6, 9, 5]`, the answer is `4`. One longest increasing subsequence is `[2, 3, 6, 9]`.

![[Screenshot 2026-11-11 at 5.07.45 PM.jpg|500]]

To solve this dynamic programming question, do:

1. Find an appropriate subproblem to the question

The sub problem we choose is finding the last element of a subsequence, or more formally stated:
- The subproblem is `dp[i]` = the length of the longest increasing subsequence that ends exactly at index `i`.


Take `[3, 1, 8, 2, 5]` and suppose we want a subsequence ending at `5`.

Its previous element can be `3`, `1`, or `2`, since each comes before `5` and is smaller than it. If we already know the best subsequence ending at each of those positions, we can take the longest one and append `5`. 

Here, the best one ends at `2` and is `[1, 2]`, so we get `[1, 2, 5]`.

If there’s no earlier smaller element, the subsequence ending there has length `1`. Once you’ve tried every endpoint, take the largest `dp[i]`.


2. Find relationships amongst subproblems

Well, we've sort of already found that relationship in the earlier, when we are looking at a specific index `dp[i]`, we look at the earlier indices and consider the best subsequence ending at each of those positions.  Then we see which ones we can append the current element (`5` in our example) to and pick the one that gives us the longest subsequence.

To formalize that, we can write the problem for $\mathrm{LIS}[k]$ as:
- $\mathrm{LIS}[k] = 1 + \max\{\mathrm{LIS}[j] \mid 0 \le j < k,\ a[j] < a[k]\}$

The `1` counts the current element. Before taking the max, we only keep the earlier positions where `a[j] < a[k]`, since we can append `a[k]` to the subsequences ending with a value smaller than itself.

In our example, we can append `5` after `3`, `1`, or `2`. Those are at indices `0`, `1`, and `3`:

$\mathrm{LIS}[4] = 1 + \max\bigl(\mathrm{LIS}[0], \mathrm{LIS}[1], \mathrm{LIS}[3]\bigr) = 3$


3. Generalize That One Observed Relationship

So more generally, we can say this now:

to find the longest increasing subsequence at a index, we have to find the largest longest increasing subsequences that it can append to from the previous indexes.


4. Implementation by solving subproblems

At this point, this already looks like a recursive problem. The LIS ending at an index depends on the LIS ending at earlier indices, and those can depend on even earlier indices. So we need a base case.

If there’s no earlier element smaller than `a[k]`, then `a[k]` forms a subsequence on its own, so $\mathrm{LIS}[k] = 1$. This is always true at index `0`.


So, in pseudocode, it looks something like this:

```python
function LIS_LENGTH(a):
    memo = empty map

    function LIS(k):
        if k is in memo:
            return memo[k]

        best = 1  // a[k] by itself

        for j = 0 to k - 1:
            if a[j] < a[k]:
                best = max(best, 1 + LIS(j))

        memo[k] = best
        return best

    answer = 0
    for k = 0 to length(a) - 1:
        answer = max(answer, LIS(k))

    return answer
```


## Bus Stacking

Given $n$ boxes $[(L_1, W_1, H_1), (L_2, W_2, H_2), \ldots, (L_n, W_n, H_n)]$, where box $i$ has length $L_i$, width $W_i$, and height $H_i$, find the height of the tallest possible stack.

Box $i$ can sit on top of box $j$ only if $L_i < L_j$ and $W_i < W_j$. The height of a stack is the sum of the heights of its boxes.


For example, given boxes [(2, 3, 3 ), (2, 2, 4), (4, 4, 2)], the best combination we could get is:

Put $(2, 2, 4)$ on top of $(4, 4, 2)$ for a total height of $4 + 2 = 6$.

![[Screenshot 2026-11-11 at 6.20.13 PM.jpg|500]]



1. Find an appropriate subproblem

Well, if we consider this question, natural constraints arise, as certain boxes can only be placed on top of certain other boxes, and we naturally have a directed acyclic graph (DAG).

In it, each box is a node, and we draw an arrow from a box to any box that can sit on top of it, therefore, valid stack is a path through this graph.

![[Screenshot 2026-11-11 at 6.34.05 PM.jpg|500]]

So for example, in this DAG, let’s find the tallest stack we can make with the red box $(4, 5, 3)$ as the base.

On top of the red box, we can place a stack whose bottom box is one of these three:

- The orange box $(2, 3, 2)$ gives us a stack of height $4$.
- The blue box $(2, 4, 1)$ gives us a stack of height $3$.
- The purple box $(1, 2, 2)$ gives us a stack of height $2$.

The yellow box $(3, 6, 2)$ is too wide to fit on the red box. So we take the tallest stack that fits and add the red box’s own height, giving us $3 + \max(4, 3, 2) = 7$.


2. Find relationships among subproblems

So for example, in this DAG, let’s find the tallest stack we can make with the red box $(4, 5, 3)$ as the base.

On top of the red box, we can place a stack whose bottom box is one of these three:
- The orange box $(2, 3, 2)$ gives us a stack of height $4$.
- The blue box $(2, 4, 1)$ gives us a stack of height $3$.
- The purple box $(1, 2, 2)$ gives us a stack of height $2$.

We take the tallest stack that fits and add the red box’s own height, giving us $3 + \max(4, 3, 2) = 7$.

![[Screenshot 2026-11-11 at 6.39.37 PM.jpg|500]]


4. Generalize the relationship

So more generally, suppose we use box $(L_i, W_i, H_i)$ as the base. Let $S$ be the set of all boxes $(L_j, W_j, H_j)$ that can sit directly on top of it. A box belongs to $S$ if $L_j < L_i$ and $W_j < W_i$.

We take the tallest stack we can put on top of the base and add the base’s own height $H_i$.

$\mathrm{height}[(L_i, W_i, H_i)]  = H_i + \max{\mathrm{height}[(L_j, W_j, H_j)] \mid (L_j, W_j, H_j) \in S}$

- If $S$ is empty, the stack is just the base box, so $\mathrm{height}[(L_i, W_i, H_i)] = H_i$.


So in pseudocode, it looks something like this:

```python
function TALLEST_STACK(boxes):
    memo = empty map

    function HEIGHT(i):
        if i is in memo:
            return memo[i]

        bestAbove = 0

        for each box j in boxes:
            if L[j] < L[i] and W[j] < W[i]:
                bestAbove = max(bestAbove, HEIGHT(j))

        memo[i] = H[i] + bestAbove
        return memo[i]

    answer = 0
    for each box i in boxes:
        answer = max(answer, HEIGHT(i))

    return answer
```
