When we look at algorithms, we look at 2 aspects:
- finding a solution first
- find a 'good' solution

But what is 'good'? Under the premise of being able to solve the problem, algorithm efficiency has become the primary evaluation criterion for measuring the quality of algorithms.

- **Time efficiency**: The length of time the algorithm runs.
- **Space efficiency**: The size of memory space the algorithm occupies.

In short, our goal is to design data structures and algorithms that are "both fast and memory-efficient".

But how? As all sayings go, all roads lead to Rome, we might have multiple algorithms that solve the same problem, how do we know which is better?

There's just 2 ways:
- run it
- estimate (eyeball) it


---

## Estimations

When we 'estimate' how complex an algorithm is, this is called asymptotic complexity analysis.

We'll go over some rules of this method, so we can analyze the complexity of simple algorithms systematically.

Next with (Asymptotic Notation)


Determining the exact runtime of an algorithm isn't usually worth the effort, we are usually just interested in when the runtime gets very large, called the asymptotic efficiency of the algorithm.

The idea simply idea, leading coefficient and lower-order terms fell away.

$\Theta$ – theta  
$O$ – oh (big-oh)  
$\Omega$ – omega (big-omega)


For theta, it's formal definition is as:
$\Theta(g(n)) = {f(n) : \text{there exist positive constants } c_1, c_2, n_0 \text{ such that } 0 \le c_1g(n) \le f(n) \le c_2g(n) \text{ for all } n \ge n_0}$

Confusing, isn't it? Let's look at an example.

![[Screenshot 2026-09-25 at 8.42.41 PM.jpg|500]]

Notice how our function $f(n)$ is sandwiched in between $c_1g(n)$ and $c_2g(n)$ beyond a certain value $n_0$, this is what it means for theta.


We could test with a real example:

$c_1n^2 \le \frac{1}{2}n^2 + 2n + 4 \le c_2n^2$


How can we find the corresponding $c_1$ and $c_2$? Well, we split the inequality.

![[Screenshot 2026-09-25 at 8.52.46 PM.jpg|500]]

For the left-hand inequality, we can choose $c_1 = \frac{1}{2}$ for all $n \ge 1$. For the right-hand inequality, we can choose $c_2 = 1$ for all $n \ge 6$. 

Combining both constraints, we choose $c_1 = \frac{1}{2}$, $c_2 = 1$, and $n_0 = 6$, so both inequalities hold for all $n \ge n_0$.


For big O, it's formal definition is as:
$O(g(n)) = {f(n) : \text{there exist positive constants } c \text{ and } n_0 \text{ such that } 0 \le f(n) \le cg(n) \text{ for all } n \ge n_0}$

Visually, its a very similar idea to theta. Notice how our function $f(n)$ is always smaller than $c \cdot g(n)$ beyond a certain value $n_0$, this is what it means for big O.

![[Screenshot 2026-09-25 at 8.58.07 PM.jpg|500]]


As for omega, it's formal definition is as:
$\Omega(g(n)) = {f(n) : \text{there exist positive constants } c \text{ and } n_0 \text{ such that } 0 \le cg(n) \le f(n) \text{ for all } n \ge n_0}$

Visually, it's the reverse to big O! Notice how our function $f(n)$ is always larger than $c \cdot g(n)$ beyond a certain value $n_0$.
