Unlike the previous shortest path algorithms we've talked about, where we only find the shortest path between a node and other nodes. Floyed-Warshell finds the shortest path between all nodes to all nodes, but it's also the slowest out of all of them.

We will go over an example with this graph:

![[Screenshot 2026-11-10 at 10.25.00 AM.jpg|200]]

We will create a distance array that keeps track of the shortest path between nodes, for example, `[3,4]` would store the shortest path rom node 3, to node 4.

![[Screenshot 2026-11-10 at 10.26.19 AM.jpg|300]]

Then, for each edge in the graph, there must be a connection between 2 nodes, and we will fill in the cost of each direct connection between the 2 nodes. 
- For example, if there’s an edge `3 → 4` with weight `7`, set `D[3][4] = 7`.

We loop through all the edges and add their weights as the direct connection distance.

![[Screenshot 2026-11-10 at 10.33.23 AM.jpg|500]]

This, simply is the distance between nodes given in the adjacency matrix.

Then, we go through 3 big for loops, it looks very imitating, but we will explain the core idea behind it, we will build up all intermediate routes between nodes i and j to find the optimal path.

What does that mean? Well, suppose currently in our adjacency matrix, it tell us that the shortest distance from `a` to `b` is `D[a][b] = 11`, this is the direct connection.

![[Screenshot 2026-11-10 at 10.49.57 AM.jpg|500]]

Suppose there exists a third node `c`, and if `D[a][c]` + `D[c][b] < D[a][b]`, that means we have a shorter path between `a` and `b`, by first `a` going to `c`, then going to `b`.

![[Screenshot 2026-11-10 at 10.50.07 AM.jpg|500]]

With that idea in mind, let’s look at the three loops. 
- The starting node `a` is `i` .
- The destination `b` is `j`.
- The intermediate node `c` is `k`.

```python
for k from 1 to V:
    for i from 1 to V:
        for j from 1 to V:
            if D[i][k] + D[k][j] < D[i][j]:
                D[i][j] = D[i][k] + D[k][j]
```

The general idea of this loop is:
1. Pick a vertex `k` to try as an intermediate stop.
2. Keep that same `k` while `i` goes through every starting node and `j` goes through every destination. For each pair, check whether going from `i` to `k` and then from `k` to `j` is cheaper. If it is, update `D[i][j]`.
3. Once we’ve checked every pair with that `k`, move to the next vertex and do it again.

![[Pasted image 20261110111125.png|500]]

Here’s where the passes build on each other. 
-  When `k = 1`, we find the best routes that can use vertex `1` in the middle.
-  When `k = 2`, the routes from `i` to `2` and from `2` to `j` can already go through vertex `1`, because we updated those distances on the previous pass, and so on.
	- So a route we find on this pass can go through both `1` and `2`. 

After the final pass, every vertex has been allowed in the middle, and `D` gives the shortest distances for all pairs in our graph.

## Pseudocode

```python
let V = number of vertices in graph
let dist = V × V array of minimum distances

for each vertex v
    dist[v][v] ← 0

for each edge (u, v)
    dist[u][v] ← weight(u, v)

for k from 1 to V
    for i from 1 to V
        for j from 1 to V
            if dist[i][j] > dist[i][k] + dist[k][j]
                dist[i][j] ← dist[i][k] + dist[k][j]
            end if
```
