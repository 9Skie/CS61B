Space complexity measures the growth trend of memory space occupied by an algorithm as the data size increases. This concept is very similar to time complexity, except that "running time" is replaced with "occupied memory space".

Unlike time complexity, **we usually only focus on the worst-case space complexity**. This is because memory space is a hard requirement, and we must ensure that sufficient memory space is reserved for all input data.

The memory space used by an algorithm during execution mainly includes the following types.

- **Input space**: Used to store the input data of the algorithm.
- **Temporary space**: Used to store variables, objects, function contexts, and other data during the algorithm's execution.
- **Output space**: Used to store the output data of the algorithm.

Temporary space can be further divided into three parts.

- **Temporary data**: It's just data
- **Stack frame space**: Used to save the context data of called functions.
- **Instruction space**: Used to save compiled program instructions (ignored)

You might wonder then, if time complexity is mostly about the number of loops we have in our operations, what is space complexity comprised of? Data structures! If we throw names at you directly, you won't understand all of them right now, but we'll do so anyways.

| Space Complexity | Example                                                                                         |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| $O(1)$           | A few variables such as `x`, `max`, or `count`, regardless of input size                        |
| $O(\log n)$      | Recursive binary search, because the recursion stack has depth $\log n$                         |
| $O(n)$           | An array, list, hash set, or queue containing up to $n$ elements                                |
| $O(n\log n)$     | A table storing $n$ entries with $\log n$ information per entry, such as a binary-lifting table |
| $O(n^2)$         | An $n\times n$ matrix, such as an adjacency matrix or 2D dynamic-programming table              |
| $O(2^n)$         | Storing information for every subset of $n$ elements, such as subset DP                         |
| $O(n!)$          | Storing every possible permutation of $n$ elements                                              |
