A binary search tree is a special type of binary tree with very fast operational speeds on search, insert, and delete, all being $O(\log(n))$

1. For the root node, the value of all nodes in the left subtree  the value of the root node  the value of all nodes in the right subtree.
2. The left and right subtrees of any node are also binary search trees, they satisfy condition `1.` as well.

So by default, we can see that a binary search tree is sorted.

## Searching for a Node

Surprisingly alike binary search (why do you think it's named binary search tree?). 

We start at the root node and compare the search value to the current node. If the search value is smaller than the current node, we move to the left child of the current node, if it's larger move to the right child.

We repeat this process until we either find a node with the search value, or each a leaf node that doesn't contain the search value, which means this value we are searching for doesn't exist in this tree.

![[Pasted image 20260921151724.png|500]]

```python
def search(self, num: int) -> TreeNode | None:

    """Search node"""
    cur = self._root
    
    # Loop search, exit after passing leaf node
    while cur is not None:
    
        # Target node is in cur's right subtree
        if cur.val < num:
            cur = cur.right
            
        # Target node is in cur's left subtree
        elif cur.val > num:
            cur = cur.left
        
        # Found target node, exit loop
        else:
            break
            
    return cur
```

## Inserting a Node

If the tree is empty... it's as simple as making the inserted node the root node.

Otherwise, we start at the root node and compare the inserted value with the current node. If the inserted value is larger, we move to the current node's right children and repeat the comparison, if it's smaller... well, left children, and we repeat the comparison.
- We continue this process until we reach a null child, meaning the node doesn't have a left or right child, or both.

Now , depending on whether the inserted value is greater or smaller than the last node, the inserted value becomes a right or left child of the last node, and the inserted value will always be a leaf node.

![[Pasted image 20260921152814.png|500]]

In the code implementation, note the following two points:

- Binary search trees do not allow duplicate nodes; otherwise, the tree would no longer satisfy its definition. Therefore, if the node to be inserted already exists in the tree, the insertion is skipped and the function returns directly.

- To implement the node insertion, we need to use node `pre` to save the node from the previous loop iteration. This way, when traversing to `None`, we can obtain its parent node, thereby completing the node insertion operation.

```python
def insert(self, num: int):
    """Insert node"""
    
    # If tree is empty, initialize root node
    if self._root is None:
        self._root = TreeNode(num)
        return
        
    # Loop search, exit after passing leaf node
    cur, pre = self._root, None
    
    while cur is not None:
    
        # Found duplicate node, return directly
        if cur.val == num:
            return
        pre = cur
        
        # Insertion position is in cur's right subtree
        if cur.val < num:
            cur = cur.right
            
        # Insertion position is in cur's left subtree
        else:
            cur = cur.left
            
    # Insert node
    node = TreeNode(num)
    
    if pre.val < num:
        pre.right = node
    else:
        pre.left = node
```

## Deleting a Node

This is the most complicated part! There's 3 separate cases that we have to consider when deleting a node.


Case 1: We delete a leaf node

We can simply remove the node from the tree without affecting other nodes. Just by setting it's parents pointer to null, detaching the leaf.

![[Pasted image 20260921154726.png|500]]


Case 2: We delete a node with 1 children

The children of the node just takes the node's position. By setting the node's parent's pointer to it's children instead of itself, and setting the node's children pointer to null.

![[Pasted image 20260921155205.png|500]]


Case 3: We delete a node with 2 children

We find the node’s **in-order successor**, which is the **smallest node in its right subtree**. To find it, move to the right child, then keep moving left until there is no left child. Copy the successor’s value into the node we want to delete, then delete the successor from its original position.

This reduces the problem to Case 1 or Case  because the successor cannot have a left child, if it did, that child would be smaller, so the successor would not be the smallest node in the right subtree. 
- Therefore, the successor is either a leaf or a node with only a right child.

Alternatively, we can use the in-order predecessor, which is the largest node in the left subtree. 
- The same idea applies: copy its value into the node, then delete the predecessor from its original position. It can only be a leaf or a node with a left child.

```python
def remove(self, num: int):
    """Delete node"""
    # If tree is empty, return directly
    if self._root is None:
        return
    # Loop search, exit after passing leaf node
    cur, pre = self._root, None
    while cur is not None:
        # Found node to delete, exit loop
        if cur.val == num:
            break
        pre = cur
        # Node to delete is in cur's right subtree
        if cur.val < num:
            cur = cur.right
        # Node to delete is in cur's left subtree
        else:
            cur = cur.left
    # If no node to delete, return directly
    if cur is None:
        return

    # Number of child nodes = 0 or 1
    if cur.left is None or cur.right is None:
        # When number of child nodes = 0 / 1, child = null / that child node
        child = cur.left or cur.right
        # Delete node cur
        if cur != self._root:
            if pre.left == cur:
                pre.left = child
            else:
                pre.right = child
        else:
            # If deleted node is root node, reassign root node
            self._root = child
    # Number of child nodes = 2
    else:
        # Get next node of cur in inorder traversal
        tmp: TreeNode = cur.right
        while tmp.left is not None:
            tmp = tmp.left
        # Recursively delete node tmp
        self.remove(tmp.val)
        # Replace cur with tmp
        cur.val = tmp.val
```

## Efficiency of Binary Search Trees

Given a set of data, we consider using an array or a binary search tree for storage. 

All operations in a binary search tree have logarithmic time complexity, providing stable and efficient performance. Arrays are more efficient than binary search trees only in scenarios with high-frequency additions and low-frequency searches and deletions.

|Operation|Unsorted array|Binary search tree|
|---|---|---|
|Search element|$O(n)$|$O(\log n)$|
|Insert element|$O(1)$|$O(\log n)$|
|Remove element|$O(n)$|$O(\log n)$|

In the ideal case, a binary search tree is balanced, so any node can be found within $O(\log n)$ loop iterations.

However, if we continuously insert and remove nodes in a binary search tree, it may degenerate into a linked list, where the time complexity of various operations also degrades to $O(n)$.
