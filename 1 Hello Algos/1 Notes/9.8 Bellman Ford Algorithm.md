Bellman–Ford, similar to Dijkstra, are both single-source shortest-path algorithms. They find the shortest distances from one starting node to the other nodes.

However... it's much slower than Dijkstra's, so it's much less used, but it can work with negative graph weights, instead of positive ones.

But how can even negative cycles exist in the first place? 

Negative cycles can show up when edge weights represent **net costs or gains**. A classic example is currency exchange.

Suppose you convert `100 USD → EUR → GBP → USD` and end up with `102 USD` after fees. You’re back at the same currency, but you gained money by going around the loop.
- But trying to do triangular arbitrage at a mass scale is generally considered illegal.

3rd iteration, 4th iteration... when do we stop? We stop if nothing improves (changes) in the graph of shortest distance estimations, meaning that we have came to the optimal shortest distances already.

Bellman–Ford makes `V - 1` full passes over all the edges by default.  If there’s no reachable negative cycle, a shortest path can always be chosen without repeating a vertex, so it uses at most `V - 1` edges. Each pass guarantees that paths using one more edge have been accounted for.

## Pseudocode 

https://www.youtube.com/watch?v=lyw4FaxrwHg

Assume these things:
- `E` is the number of edges.
- `V` is the number of vertices.
- `S` is the ID of the starting node.
- `D` is an array of size `V` that tracks the best distance from `S` to each node.

```python
function bellmanFord(graph, V, S):
    D = array of size V filled with +∞
    D[S] = 0

    for (i = 0; i < V - 1; i = i + 1):
        changed = false

        for edge in graph.edges:
            if D[edge.from] + edge.cost < D[edge.to]:
                D[edge.to] = D[edge.from] + edge.cost
                changed = true

        // Stop if the entire pass made no updates.
        if changed == false:
            return D

    // Mark nodes affected by reachable negative cycles.
    for (i = 0; i < V - 1; i = i + 1):
        for edge in graph.edges:
            if D[edge.from] + edge.cost < D[edge.to]:
                D[edge.to] = −∞

    return D
```

p checks whether reaching `edge.to` through `edge.from` gives a shorter route. Each full pass guarantees that routes using one more edge have been accounted for. A finite shortest path can be chosen without repeating vertices, so `V - 1` passes are enough. If a whole pass makes no changes, you can return `D` early.

If a distance can still decrease after `V - 1` passes, a reachable negative cycle is affecting it. The second loop marks those distances as `−∞` and propagates that mark to nodes reachable from the cycle. If `V = 1` and self-loops are allowed, run the cycle check at least once.

In the returned array, a finite value is the shortest distance, `+∞` means the node is unreachable, and `−∞` means the cost can be lowered indefinitely. The edge scans take `O(VE)` time, and `D` uses `O(V)` extra space.
