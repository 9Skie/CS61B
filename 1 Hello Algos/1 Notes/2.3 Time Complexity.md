Time complexity analysis does not count the algorithm's runtime, **but rather counts the growth trend of the algorithm's runtime as the data volume increases**.

Suppose we have 3 algorithms, and there is an input size $n$ for all these algorithms.

```python
# Time complexity of algorithm A: constant order
def algorithm_A(n: int):
    print(0)
    
# Time complexity of algorithm B: linear order
def algorithm_B(n: int):
    for _ in range(n):
        print(0)
        
# Time complexity of algorithm C: constant order
def algorithm_C(n: int):
    for _ in range(1000000):
        print(0)
```

So, we see 'constant order' and 'linear order', what does that mean?
- constant order: the algorithm doesn't grow with the size of n
- linear order: the algorithm linearly grows with the size of n

**Time complexity can effectively evaluate algorithm efficiency**. For example, the runtime of algorithm `B` grows linearly; when  it is slower than algorithm `A`, and when $n > 1000000$ it is slower than algorithm `C`.


## Asymptotic Upper Bound

Consider the code:

```python
def algorithm(n: int):
    a = 1      # +1
    a = a + 1  # +1
    a = a * 2  # +1
    
    # Loop n times
    for i in range(n):  # +1
        print(0)        # +1
```

Let the number of operations of the algorithm be a function of the input data size , denoted as . Then the number of operations of the above function is

$T(n) = 3 + 2n$

We denote the time complexity of linear order as $O(n)$. This mathematical notation is called **Big-O notation**, representing the **asymptotic upper bound** of the function $T(n)$.

The formal definition of the asymptotic upper bound of function is:

If there exist positive real numbers $c$ and $n_0$ such that for all $n>n_0$, we have $T(n)\le c\cdot f(n)$, then $f(n)$ can be considered an asymptotic upper bound of $T(n)$, denoted as $T(n)=O(f(n))$.

![[Pasted image 20260917182751.png|500]]

So in other words, beyond some constant $n_0$, when n tends to infinity, there exists at least one constant $c$ such that $c\cdot f(n)\ge T(n)$ for every $n\ge n_0$. 

Therefore, asymptotically, $T(n)$ grows no faster than a constant multiple $c \cdot f(n)$.

## Deriving $f(n)$

According to the definition, after determining $f(n)$, we can obtain the time complexity $f(n)$. So how do we determine the asymptotic upper bound $f(n)$?


1 Count the number of operations

For Big-O analysis, we only care about how the operation count grows with $n$, so constant terms and constant coefficients can be ignored.

1. Ignore constant terms.
    - Terms that do not depend on $n$ do not affect asymptotic growth.
    - $T(n)=n+5\rightarrow O(n)$
    
2. Ignore constant coefficients.
    - Multiplying $n$ by a constant does not change its growth rate.
    - $T(n)=2n \rightarrow O(n)$
    - $T(n)=5n+1 \rightarrow O(n)$
    
3. Multiply nested loops.
    - If one loop runs $n$ times and an inner loop also runs $n$ times, the total work is $n\cdot n=n^2$, so the time complexity is $O(n^2)$.



2 Determine the Asymptotic Upper Bound

**Time complexity is determined by the highest-order term in** $T(n)$ . This is because as  tends to infinity, the highest-order term will play a dominant role, and the influence of other terms can be ignored.


3 Common Bounds (And Who's Larger)

Common time complexities, ordered from lower growth to higher growth, are:

$O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2) < O(2^n) < O(n!)$

Constant $<$ Logarithmic $<$ Linear $<$ Linearithmic $<$ Quadratic $<$ Exponential $<$ Factorial
