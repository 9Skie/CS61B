Dynamic programming decomposes a problem into a series of smaller subproblems and avoids redundant computation by storing the solutions to subproblems, thereby significantly improving time efficiency.


Let's take this question: Given a staircase with `n` steps, where you can climb 1 or 2 steps at a time, how many different ways are there to reach the top?

For example, for a 3 step staircase, there are 3 solutions to reach the top.

![[Pasted image 20260923172713.png|500]]


We can solve with backtracking (brute force), and it would be like enumerating all possibilities of how to step up the stairs.

1. **Start at the ground**, with the number of valid ways set to $0$.
2. **Make a choice:** climb either $1$ or $2$ steps.
3. **Explore that choice:** repeat the process from the new position. If you reach the top exactly, add $1$ to the count; if you go past it, stop that branch.
4. **Backtrack:** return to the previous position and try the other choice.
5. Continue until **all possible sequences have been explored**, then return the count.

```python
def backtrack(choices: list[int], state: int, n: int, res: list[int]) -> int:
    """Backtracking"""
    # When climbing to the n-th stair, add 1 to the solution count
    if state == n:
        res[0] += 1
    # Traverse all choices
    for choice in choices:
        # Pruning: not allowed to go beyond the n-th stair
        if state + choice > n:
            continue
        # Attempt: make a choice, update state
        backtrack(choices, state + choice, n, res)
        # Backtrack

def climbing_stairs_backtrack(n: int) -> int:
    """Climbing stairs: Backtracking"""
    choices = [1, 2]  # Can choose to climb up 1 or 2 stairs
    state = 0  # Start climbing from the 0-th stair
    res = [0]  # Use res[0] to record the solution count
    backtrack(choices, state, n, res)
    return res[0]
```


We can write this recursively:

```python
def dfs(i: int) -> int:
    """Search"""
    # Known dp[1] and dp[2], return them
    if i == 1 or i == 2:
        return i
    # dp[i] = dp[i-1] + dp[i-2]
    count = dfs(i - 1) + dfs(i - 2)
    return count

def climbing_stairs_dfs(n: int) -> int:
    """Climbing stairs: Search"""
    return dfs(n)
```

This forms a recursion tree where each call to `dfs(i)` branches into `dfs(i - 1)` and `dfs(i - 2)`, until reaching the base cases `dfs(1)` and `dfs(2)`. The same subproblems appear repeatedly in different branches, causing redundant computation.

![[Pasted image 20260923174305.png|500]]

Observing this image, the exponential time complexity is caused by "overlapping subproblems". For example, $dp[9]$ is decomposed into $dp[8]$  and $dp[7]$, and $dp[8]$ is decomposed into $dp[7]$ and $dp[6]$ , both of which contain the subproblem $dp[7]$.

So... can we re-use some of those answers for the smaller problems? This is the core of dynamic programming
- Do note that this does require additional memory to remember the answer to those subproblems.

Yes! In face, there's 2 ways we can take this, we can either go top down or bottom up... and they are both dynamic programming approaches.

## Memoization

For wanting all overlapping subproblems to be computed only once, we declare an array `mem` to record the solution to each subproblem and prune overlapping subproblems during the search process.

1. When computing $dp[i]$ for the first time, we record it in `mem[i]` for later use.
2. When we need to compute $dp[i]$ again, we can directly retrieve the result from `mem[i]`, thereby avoiding redundant computation of that subproblem.

![[Pasted image 20260923174923.png|500]]

```python
def dfs(i: int, mem: list[int]) -> int:
    """Memoization search"""
    # Known dp[1] and dp[2], return them
    if i == 1 or i == 2:
        return i
    # If record dp[i] exists, return it directly
    if mem[i] != -1:
        return mem[i]
    # dp[i] = dp[i-1] + dp[i-2]
    count = dfs(i - 1, mem) + dfs(i - 2, mem)
    # Record dp[i]
    mem[i] = count
    return count

def climbing_stairs_dfs_mem(n: int) -> int:
    """Climbing stairs: Memoization search"""
    # mem[i] records the total number of solutions to climb to the i-th stair, -1 means no record
    mem = [-1] * (n + 1)
    return dfs(n, mem)
```

## Tabulation

Memoization is top-down, where we start by asking for the answer to the original problem, recursively request the smaller answers it depends on, and save each result.

Tabulation is bottom-up, where we start with the smallest known answers, then use a loop to calculate progressively larger answers until reaching the original problem.

For the staircase problem, let $dp[i]$ represent the number of ways to climb $i$ stairs. We already know:

$dp[1]=1$ and $dp[2]=2$

Every later answer follows the same recurrence:

$dp[i]=dp[i-1]+dp[i-2]$

Instead of recursively asking for these smaller answers, we fill the table in an order that guarantees they are already available:

1. Store the known answers: $dp[1]=1$ and $dp[2]=2$.
2. Calculate $dp[3]=dp[2]+dp[1]=3$.
3. Calculate $dp[4]=dp[3]+dp[2]=5$.
4. Continue until we have calculated $dp[n]$, then return it.

For $n \geq 1$, the implementation is:

```python
def climbing_stairs_dp(n: int) -> int:
    """Climbing stairs using tabulation."""
    if n == 1 or n == 2:
        return n

    # Store the answer to each subproblem
    dp = [0] * (n + 1)

    # Fill in the known answers
    dp[1], dp[2] = 1, 2

    # Build larger answers from smaller ones
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]
```

The array `dp` serves the same storage purpose as `mem` in memoization. However, there are no recursive calls or pending returns: each loop iteration reads two completed entries and writes the next one.

---

There are additional constraints for a problem to be considered suitable for dynamic programming's optimization.
- **Optimal substructure:** An optimal solution to the original problem can be constructed from optimal solutions to its smaller subproblems.
- **No aftereffects:** Once the current state is known, future choices and their outcomes do not depend on any additional history. The state must contain all the information needed to solve the remaining problem.
