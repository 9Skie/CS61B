But, how do we actually algorithmically find those eulerian circuits/paths?

Well, as we recall, the graph itself must first satisfy some properties first:

| Graph type | Eulerian circuit/Closed Path                   | Open Eulerian path                                                                                              |
| ---------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Undirected | Every vertex has even degree.                  | Exactly two vertices have odd degree. In the second case, those two vertices are the endpoints.                 |
| Directed   | Every vertex has equal indegree and outdegree. | The start has one extra outgoing edge, the end has one extra incoming edge, and every other vertex is balanced. |


This means before we even try to find to find some eulerian circuit/path, we need to first see if these properties are satisfied. 

Assume we have this directed graph:

![[Screenshot 2026-11-10 at 10.29.16 PM.jpg|500]]

We first count the in/out degrees of each node by looping through all the edges, for each edge, increment the in degree of a node (that the edge is pointing to) and increment the out degree of a node (that the edge is pointed from)

![[Screenshot 2026-11-10 at 10.30.43 PM.jpg|500]]

Once this graph has been filled up...

![[Screenshot 2026-11-11 at 11.38.48 AM.jpg|500]]

We need to verify that:
1. For every vertex, `outdegree − indegree` must be `−1`, `0`, or `+1`.
2. The differences must fit one of these patterns.
   - Circuit: Every difference is `0`, so all vertices are balanced.
   - Open Path: Exactly one vertex has `+1` (the start), exactly one has `−1` (the end), and every other vertex has `0`.

Next is finding a valid starting/ending edge:
- Eulerian open path: The vertex with `outdegree − indegree = +1` is the start, and the vertex with `−1` is the end.
- Eulerian circuit / closed path: If every vertex is balanced, we can start at any vertex with at least one outgoing edge.


Now then, we need to actually find the eulerian path, how do we do that? It's a modified version of the DFS search, this is the true Hierholzer's algorithm.

We perform DFS until we get stuck (or in other words, when the current node has no unvisited outgoing edges) , with a few differences:
- Each time we follow an outgoing edge, we mark that edge as used. 
- We can revisit a vertex whenever we reach it through a different unused edge.

Then, we put the node which we got stuck on at the front of the result, then we backtrack.

While backtracking, if the current node has any remaining unvisited edges, we follow them calling our DFS method recursively to extend the Eulerian path.


Confusing? Let's look at an example.

So say, in this graph we began at node 0 and performed DFS, and got stuck on node 4.

![[Screenshot 2026-11-10 at 11.34.31 PM.jpg|500]]

We first put node 4 at the front of the solution, and begin backtracking at 3.

Solution: `[4]`


![[Screenshot 2026-11-10 at 11.37.13 PM.jpg|500]]

Since 3 is also stuck, we put it at the front of solution as well:

Solution: `[3, 4]`


We get to 1, it has remaining edges that we have not visited, so we call DFS on its out going edge, which goes to node 2, and then back to node 1.

![[Screenshot 2026-11-11 at 11.40.02 AM.jpg|500]]

And so now, node 1 is stuck, and therefore we again put it in front of the solution:

Solution: `[1, 3, 4]`


Backtrack to node 2, it's stuck.

![[Screenshot 2026-11-11 at 11.40.14 AM.jpg|500]]

Solution: `[2, 1, 3, 4]`

then back track to node 1, it's stuck.

![[Screenshot 2026-11-11 at 11.40.28 AM.jpg|500]]

Solution: `[1, 2, 1, 3, 4]`


Then back track to node 0, it's stuck... and we have our final solution.

Solution: [0, 1, 2, 1, 3, 4]



So now that you understand how this process works, lets return to our original graph problem, say through DFS starting at node 1, we end up stuck at node 6.

In this process, we have to keep track of 2 things:
- we decrease the relevant out edges from the table that the DFS has traversed through.
- we also keep track of which edge we've went to/ haven't went to by using the adjacency list. 
	- When DFS takes an edge, it removes that edge from the list before recursing

I'm not gonna go through the entire process again, but basically through backtracking, we get to this solution:

Solution = `[1, 3, 5, 6, 3, 2, 4, 3, 1, 2, 2, 4, 6]`

## Pseudocode

```python
# Global/class scope variables
n = number of vertices in the graph
m = number of edges in the graph
g = adjacency list representing directed graph

in  = [0, 0, ..., 0, 0] # Length n
out = [0, 0, ..., 0, 0] # Length n

path = empty integer linked list data structure

function findEulerianPath():
    countInOutDegrees()
    if not graphHasEulerianPath(): return null

    dfs(findStartNode())

    # Return eulerian path if we traversed all the
    # edges. The graph might be disconnected, in which
    # case it's impossible to have an euler path.
    if path.size() == m+1: return path
    return null

function countInOutDegrees():
    for edges in g:
        for edge in edges:
            out[edge.from]++
            in[edge.to]++

function graphHasEulerianPath():
    start_nodes, end_nodes = 0, 0
    for (i = 0; i < n; i++):
        if (out[i] - in[i]) > 1 or (in[i] - out[i]) > 1:
            return false
        else if out[i] - in[i] == 1:
            start_nodes++
        else if in[i] - out[i] == 1:
            end_nodes++
    return (end_nodes == 0 and start_nodes == 0) or
           (end_nodes == 1 and start_nodes == 1)

function findStartNode():
    start = 0
    for (i = 0; i < n; i = i + 1):
        # Unique starting node
        if out[i] - in[i] == 1: return i

        # Start at any node with an outgoing edge
        if out[i] > 0: start = i
    return start

function dfs(at):
    # While the current node still has outgoing edges
    while (out[at] != 0):
        # Select the next unvisited outgoing edge
        next_edge = g[at].get(--out[at])
        dfs(next_edge.to)

    # Add current node to solution
    path.insertFirst(at)
```
