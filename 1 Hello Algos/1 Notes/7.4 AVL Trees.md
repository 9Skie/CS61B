after multiple insertion and removal operations, a binary search tree may degenerate into a linked list. In this case, the time complexity of all operations degrades from $O(\log(n))$ to $O(n)$, which is not ideal.

![[Pasted image 20260923102759.png|500]]

![[Pasted image 20260923102816.png|500]]

In 1962, G. M. Adelson-Velsky and E. M. Landis proposed the AVL tree in their paper "An algorithm for the organization of information". The paper describes a series of operations that prevent an AVL tree from degenerating as nodes are inserted and removed, thereby keeping the time complexity of various operations at $O(\log(n))$.

So, the AVL tree is just a balanced binary search tree, but how does it do that? Through 'rotations'.

---

Since the operations related to AVL trees require obtaining node heights, we need to add a `height` variable to the node class.

```python
class TreeNode:
    """AVL tree node"""
    def __init__(self, val: int):
        self.val: int = val                 # Node value
        self.height: int = 0                # Node height
        self.left: TreeNode | None = None   # Left child reference
        self.right: TreeNode | None = None  # Right child reference
```

And we also need to add function to test and change the height.

```python
def height(self, node: TreeNode | None) -> int:
    """Get node height"""
    # Empty node height is -1, leaf node height is 0
    if node is not None:
        return node.height
    return -1

def update_height(self, node: TreeNode | None):
    """Update node height"""
    # Node height equals the height of the tallest subtree + 1
    node.height = max([self.height(node.left), self.height(node.right)]) + 1
```

The balance factor of a node is defined as the height of the node's left subtree minus the height of its right subtree, this is important to ensure the AVL property is kept.

```python
def balance_factor(self, node: TreeNode | None) -> int:
    """Get balance factor"""
    # Empty node balance factor is 0
    if node is None:
        return 0
    # Node balance factor = left subtree height - right subtree height
    return self.height(node.left) - self.height(node.right)
```

## Rotations

The characteristic of AVL trees lies in the "rotation" operation, which can restore balance to unbalanced nodes without affecting the inorder traversal sequence of the binary tree. 
- rotation operations can both maintain the property of a "binary search tree" and make the tree return to a "balanced binary tree".

There's 4 types of rotations.

![[Pasted image 20260923154813.png|500]]


Let's start with the simplest of right rotations:

1. **Identify the unbalanced node:** Node `3` is too heavy on its left side. Its left child, `1`, becomes the pivot.

![[Pasted image 20260923155104.png|500]]

2. **Move `3` down to the right of `1`:** Node `3` becomes `1`’s right child. Normally, `1`’s old right subtree becomes `3`’s left subtree; here, that subtree is empty.

![[Pasted image 20260923155110.png|500]]

3. **Connect `1` to the parent:** Replace `3` with `1` as node `4`’s left child. Node `0` remains `1`’s left child, so `1` now has children `0` and `3`, restoring balance.

![[Pasted image 20260923155118.png|500]]



Now, there's cases where the child already has a right child (grand_child) in the first place. When we make the node the right child of its left child, we also make the grandchild the left child of the node.

![[Pasted image 20260923155451.png|500]]


So in general, the 3 steps to a right rotation:
1. The **child** (the node’s left child) moves up into the node’s position.
2. The **node** becomes the child’s right child.
3. The child’s **original right subtree** becomes the node’s left subtree.

```python
def right_rotate(self, node: TreeNode | None) -> TreeNode | None:
    """Right rotation operation"""
    child = node.left
    grand_child = child.right
    # Using child as pivot, rotate node to the right
    child.right = node
    node.left = grand_child
    # Update node height
    self.update_height(node)
    self.update_height(child)
    # Return root node of subtree after rotation
    return child
```



Correspondingly, we could mirror this operation for the node's right child as well, this is called a left rotation.

![[Pasted image 20260923155640.png|500]]

Now, there are cases where the child already has a left child (`grand_child`). When we make the node the left child of its right child, we also make the grandchild the right child of the node.

![[Pasted image 20260923160335.png|500]]

Based on symmetry, we only need to replace all `left` in the right rotation implementation code with `right`, and all `right` with `left`, to obtain the left rotation implementation code:

```python
def left_rotate(self, node: TreeNode | None) -> TreeNode | None:
    """Left rotation operation"""
    child = node.right
    grand_child = child.left
    # Using child as pivot, rotate node to the left
    child.left = node
    node.right = grand_child
    # Update node height
    self.update_height(node)
    self.update_height(child)
    # Return root node of subtree after rotation
    return child
```


Then from such, we can have composite rotations, like left then right, right then left.

But, with this much possible rotations types, which do we use? We had some visual demonstrations for how to implement them, but not a systematic way to distinguish which one to use.

To choose, **first identify which side of the node is taller, then examine the child on that side**:

1. **Left-heavy node, left-heavy or balanced left child:** Perform a **right rotation on the node**. This is the **left-left case**.
    
2. **Left-heavy node, right-heavy left child:** Perform a **left rotation on the left child**, then a **right rotation on the node**. This is the **left-right case**: the first rotation straightens the bend so the second can restore balance.
    
3. **Right-heavy node, right-heavy or balanced right child:** Perform a **left rotation on the node**. This is the **right-right case**.
    
4. **Right-heavy node, left-heavy right child:** Perform a **right rotation on the right child**, then a **left rotation on the node**. This is the **right-left case**: again, straighten the bend first.

If the node’s balance factor is $-1$, $0$, or $1$, **no rotation is needed at that node**.

```python
def rotate(self, node: TreeNode | None) -> TreeNode | None:
    """Perform rotation operation to restore balance to this subtree"""
    # Get balance factor of node
    balance_factor = self.balance_factor(node)
    # Left-leaning tree
    if balance_factor > 1:
        if self.balance_factor(node.left) >= 0:
            # Right rotation
            return self.right_rotate(node)
        else:
            # First left rotation then right rotation
            node.left = self.left_rotate(node.left)
            return self.right_rotate(node)
    # Right-leaning tree
    elif balance_factor < -1:
        if self.balance_factor(node.right) <= 0:
            # Left rotation
            return self.left_rotate(node)
        else:
            # First right rotation then left rotation
            node.right = self.right_rotate(node.right)
            return self.left_rotate(node)
    # Balanced tree, no rotation needed, return directly
    return node
```

|Balance factor of the unbalanced node|Balance factor of the child node|Rotation method to apply|
|---|---|---|
|$> 1$ (left-heavy)|$\geq 0$|Right rotation|
|$> 1$ (left-heavy)|$< 0$|Left rotation then right rotation|
|$< -1$ (right-heavy)|$\leq 0$|Left rotation|
|$< -1$ (right-heavy)|$> 0$|Right rotation then left rotation|

---

Now, we know which rotations to pick when we are faced with differently unbalanced trees, but this has a further problem, when would we actually perform a rotation? Sure, we can manually call it, but when else?

The idea is that rotations happen **automatically as part of insertion and removal**, the logic goes as such.

1. **Insert or remove a node** using the normal BST procedure.
2. **Walk back up toward the root**, updating heights and checking each ancestor’s balance factor.
3. If an ancestor’s balance factor becomes **greater than 1 or less than −1**, apply the appropriate rotation to restore balance.

Insertion:

```python
def insert(self, val):
    """Insert node"""
    self._root = self.insert_helper(self._root, val)

def insert_helper(self, node: TreeNode | None, val: int) -> TreeNode:
    """Recursively insert node (helper method)"""
    if node is None:
        return TreeNode(val)
    # 1. Find insertion position and insert node
    if val < node.val:
        node.left = self.insert_helper(node.left, val)
    elif val > node.val:
        node.right = self.insert_helper(node.right, val)
    else:
        # Duplicate node not inserted, return directly
        return node
    # Update node height
    self.update_height(node)
    # 2. Perform rotation operation to restore balance to this subtree
    return self.rotate(node)
```

Deletion:

```python
def remove(self, val: int):
    """Delete node"""
    self._root = self.remove_helper(self._root, val)

def remove_helper(self, node: TreeNode | None, val: int) -> TreeNode | None:
    """Recursively delete node (helper method)"""
    if node is None:
        return None
    # 1. Find node and delete
    if val < node.val:
        node.left = self.remove_helper(node.left, val)
    elif val > node.val:
        node.right = self.remove_helper(node.right, val)
    else:
        if node.left is None or node.right is None:
            child = node.left or node.right
            # Number of child nodes = 0, delete node directly and return
            if child is None:
                return None
            # Number of child nodes = 1, delete node directly
            else:
                node = child
        else:
            # Number of child nodes = 2, delete the next node in inorder traversal and replace current node with it
            temp = node.right
            while temp.left is not None:
                temp = temp.left
            node.right = self.remove_helper(node.right, temp.val)
            node.val = temp.val
    # Update node height
    self.update_height(node)
    # 2. Perform rotation operation to restore balance to this subtree
    return self.rotate(node)
```
