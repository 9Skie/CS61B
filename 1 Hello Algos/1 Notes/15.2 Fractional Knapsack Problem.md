More Knapsack? Yep, but with another twist.

This time, while we can only select each item only once, we can select a fraction of it! With it's value being proportional to the selected weight.

![[Pasted image 20260923224233.png|500]]

The fractional knapsack problem is very similar overall to the 0-1 knapsack problem, with states including the current item  and capacity , and the goal being to maximize value under the limited knapsack capacity, the only difference is that this problem allows selecting only a fraction of an item.

- For item $i$, its value per unit weight is $val[i-1]/wgt[i-1]$, referred to as unit value.
- Suppose we put a portion of item $i$ with weight $w$ into the knapsack, then the value added to the knapsack is $w \times val[i-1]/wgt[i-1]$.

![[Pasted image 20260923224318.png|500]]

At this point, we have infinitely many possible combinations! There's no way we can understand or know the global optimal strategy for this knapsack problem, that's why we are using greedy for this.


So, how can we apply greedy to the fractional knapsack problem? We prioritize items with higher value per unit weight because each unit of capacity they occupy gives us more value. 

If we took part of a lower-unit-value item while a higher-unit-value item was still available, replacing that weight with the higher-value item would improve our answer without using more capacity.

1. Sort the items by value per unit weight, from highest to lowest.
2. Take each item in that order, as long as it fits completely.
3. If an item cannot fit completely, take just enough of it to fill the remaining capacity, then stop.

![[Pasted image 20260923225754.png|500]]

```python
class Item:
    """Item"""

    def __init__(self, w: int, v: int):
        self.w = w  # Item weight
        self.v = v  # Item value

def fractional_knapsack(wgt: list[int], val: list[int], cap: int) -> int:
    """Fractional knapsack: Greedy algorithm"""
    # Create item list with two attributes: weight, value
    items = [Item(w, v) for w, v in zip(wgt, val)]
    # Sort by unit value item.v / item.w from high to low
    items.sort(key=lambda item: item.v / item.w, reverse=True)
    # Loop for greedy selection
    res = 0
    for item in items:
        if item.w <= cap:
            # If remaining capacity is sufficient, put the entire current item into the knapsack
            res += item.v
            cap -= item.w
        else:
            # If remaining capacity is insufficient, put part of the current item into the knapsack
            res += (item.v / item.w) * cap
            # No remaining capacity, so break out of the loop
            break
    return res
```


Now, how do we know this is optimal? We can use proof by contradiction. We can prove that this greedy strategy is optimal using an exchange argument.

Suppose a solution is optimal, but it includes some weight from an item with lower value per unit weight while a higher-unit-value item is still available.

We can remove a small amount of the lower-value item and replace it with the same weight from the higher-value item. The total weight stays unchanged, so the capacity constraint is still satisfied. However, the total value increases.

This contradicts our assumption that the original solution was optimal. Therefore, an optimal solution cannot use lower-unit-value items while higher-unit-value items remain available to replace them.

![[Pasted image 20260923234158.png|500]]

By repeatedly making these exchanges, we obtain the greedy arrangement: take as much as possible of each item in descending order of unit value. This proves that the greedy strategy achieves the maximum total value. Items with equal unit value can be taken in either order。
