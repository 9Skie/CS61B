Lets look first, what are strong connected components? They are self-contained cycles within a directed graph where every vertex in a given cycle can reach every other vertex in the same cycle.
- Cycle: a cycle is a non-empty closed path or trail that starts and ends at the same vertex, with no other vertices repeated

![[Screenshot 2026-11-10 at 2.03.40 PM.jpg|500]]

These are the strongly connected components within this graph, and the idea of Tarjan's algorithm is that it finds the strongly connected components (SCCs) of a directed graph.

Anyways, to understand Tarjan's algorithm, we have to first understand low-link values.


## Low Link Value

The low link value of a node is the smallest (ID) node reachable from that node when doing a DFS (including itself).


What does that mean? Consider this graph:

![[Screenshot 2026-11-10 at 2.08.30 PM.jpg|500]]


If we look at node 1, if it tries to run a DFS, it is able to reach node 0, and therefore the low link of node 1 is node 0.

![[Screenshot 2026-11-10 at 2.10.01 PM.jpg|500]]


Now, if we run this DFS test and see the low link value of every node, we'll realize a fact, the nodes with the same low link value belong to the same strongly connected component.

![[Screenshot 2026-11-10 at 2.11.44 PM.jpg|500]]


So... if simply by running a DFS at every node we can obtain their low link values, we can already group them into different SCCs (strongly connected groups), what is the point of Tarjan's algorithm? 

The problem is that the low-link values we calculated depend on the order in which DFS assigns IDs. A node can reach a lower-ID node in another SCC, even when that other SCC cannot reach it back. This can give nodes in different SCCs the same low-link value, so grouping nodes by these values can give us the wrong components.

---

## Tarjan's Algorithm Idea

To cope with the random traversal order of the DFS, and random index assignment of nodes, Tarjan's algorithm maintains a set (as a stack) of valid nodes from which to update low-link values from。
- nodes are added to the stack of valid nodes as they are explored for the first time
- nodes are removed from the stack each time a complete SCC is found.

Let's first see an example, then we'll go into the details of how the algorithm works.


Assume this is our graph:

![[Screenshot 2026-11-10 at 2.25.25 PM.jpg|500]]

We pick a random node to start DFS, and call it node 0.

![[Screenshot 2026-11-10 at 2.26.00 PM.jpg|500]]

As we explore unvisited nodes, give them IDs in the order visited, and a low link value equal to their assigned IDs.

![[Screenshot 2026-11-10 at 2.27.19 PM.jpg|500]]

So in this case, node 1, node 2... but then we have nowhere to go with DFS, so we stop here.

Before returning from node `2`, we check its outgoing edge `2 -> 0`. Node `0` has already been visited, but it is still on the stack. So we compare the low-link value of the current node, `2`, with that of the node its edge points to, `0`.

- `min(lowlink[2], lowlink[0]) = 0`, so we update `lowlink[2]` to `0`.


Now DFS returns from node `2` to node `1`. Node `1` reached node `2` through the edge `1 -> 2`. Since node `2` is still on the stack, node `1` can use the low-link value that node `2` just found.

- `min(lowlink[1], lowlink[2]) = 0`, so we update `lowlink[1]` to `0`.

And we repeat this for node 0 and node 1 as well.


Upon returning to node 0, we realized we found an SCC, as we visited all the outgoing neighbors of node 0, and it's ID is equal to it's low length value.

![[Screenshot 2026-11-10 at 2.45.43 PM.jpg|500]]

Then, we pop off all associated nodes off the stack.


Now, we pick a new node to begin, we give it ID node 3, and it performs DFS to node 4, node 5, then to node 6...
- You'll realize we are intentionally avoiding the nodes which we've already formed a SCC with (node 0, 1, 2).

![[Screenshot 2026-11-10 at 2.50.53 PM.jpg|500]]


Now, if we repeat this process of finding the smallest low link values:

- `lowlink[6] = min(lowlink[6], lowlink[4]) = 4`
- `lowlink[5] = min(lowlink[5], lowlink[6]) = 4`
- `lowlink[4] = min(lowlink[4], lowlink[5]) = 4`

Nodes `4`, `5`, and `6` form an SCC and are removed from the stack before DFS returns to `3`. 

![[Screenshot 2026-11-10 at 2.55.32 PM.jpg|500]]


Node  3 still has another unvisited neighbor to explore, and so we continue DFS at node 3, and go to node 7, node 7 can only go back to node 3, and therefore DFS returns.

Now we start computing low link values again:

`lowlink[7] = min(lowlink[7], lowlink[3]) = 3`
- `lowlink[3] = min(lowlink[3], lowlink[7]) = 3`

Node `3` has finished checking its neighbors, and its ID equals its low-link value. So `3` is the root of an SCC. We pop nodes `7` and `3` from the stack, giving us the SCC `{3, 7}`.

## Pseudocode

```python
UNVISITED = -1
n = number of nodes in graph
g = adjacency list with directed edges

id = 0        # Used to give each node an ID
sccCount = 0  # Used to count the number of SCCs found

# Index i in these arrays represents node i
ids = [0, 0, ..., 0]                 # Length n
low = [0, 0, ..., 0]                 # Length n
onStack = [false, false, ..., false] # Length n
stack = an empty stack data structure

function findSccs():
    for (i = 0; i < n; i++):
        ids[i] = UNVISITED

    for (i = 0; i < n; i++):
        if (ids[i] == UNVISITED):
            dfs(i)

    return low
```


The dfs, as we know must be modified in this case, as we want to NOT visit nodes that already formed SCCs. 

```python
function dfs(at):
    stack.push(at)
    onStack[at] = true
    ids[at] = low[at] = id++

    # Visit all neighbours & min low-link on callback
    for(to : g[at]):
        if(ids[to] == UNVISITED): dfs(to)
        if(onStack[to]): low[at] = min(low[at], low[to])

    # After having visited all the neighbours of 'at'
    # if we're at the start of a SCC empty the seen
    # stack until we're back to the start of the SCC.
    if(ids[at] == low[at]):
        for(node = stack.pop();; node = stack.pop()):
            onStack[node] = false
            low[node] = ids[at]
            if(node == at): break
        sccCount++
```
