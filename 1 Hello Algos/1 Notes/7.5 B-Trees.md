
[B-Trees](https://www.youtube.com/watch?v=K1a2Bk8NrYQ)

A b-tree is an extension of a binary search tree, where instead of having 2 children, we have b number of children per node.

A 2–3 tree extends this idea by allowing nodes to contain either one or two values, giving them two or three children. 
- Assume we call node 1 $a$ and node 2 $b$, and our value $m$
- The left subtree contains values $m<a$
	- ![[Screenshot 2026-09-30 at 10.12.13 AM.jpg|500]]

- The middle subtree contains values $a<m<b$ 
	- ![[Screenshot 2026-09-30 at 10.12.50 AM.jpg|500]]

- The right subtree contains values $m>b$ 
	- ![[Screenshot 2026-09-30 at 10.12.31 AM.jpg|500]]

This allows more values to be represented at each level, and hense reduces the height of the tree, but this doubles the number of comparisons at each node.


It doesn't mean this is less efficient, with binary trees, we would have to repeatedly fetch individual nodes from memory, which could be like pretty inefficient.

B-trees can store however many values per node, so there's less back and fourth between memory and the CPU.

Like if we have a b-tree with 4 nodes, it will have 5 children.

![[Screenshot 2026-09-30 at 10.22.59 AM.jpg|500]]


Now, there's some rules in B-trees as well.

- While we pick the maximum number of value per node, the minimum number of value per node is half of that.
	- Except the root node

Say we are inserting values inside the root node, and we hit 5 values (when the cap is 4).

![[Screenshot 2026-09-30 at 10.28.33 AM.jpg|500]]

We don't just create a new node with 1 key, as that's illegal in B-trees, we take the smallest 2 values and make 1 node, and the biggest 2 values and make 1 node, and with the leftover middle value, turns into the root node.
 - It's illegal to have a node in a b-tree with just 1 key
	 - The only exception to that is the root node

![[Screenshot 2026-09-30 at 10.34.23 AM.jpg|500]]


This pattern repeats, as if we again have a node that's full but we need to insert a value, we do this:
- split the node into 2 nodes (smallest 2 values, largest 2 values)
- push the middle value into the parent

You might wonder, then what happens when the root node is full? Like here we are trying to insert 23.

![[Screenshot 2026-09-30 at 10.38.39 AM.jpg|500]]

Well, the idea of splitting a node is recursive, if the parent is already full, then inserting that middle value causes the **parent itself to overflow**, so we perform exactly the same operation again:
- split the overflowing parent into two nodes
- push its middle value into _its_ parent

This process can continue upward through several levels of the tree.

Eventually, one of two things happens. Either we reach a parent that still has room, in which case we insert the promoted value there and stop, or the overflow reaches the **root**.

In this example that they gave, the overflow directly reached the root, so the root also follows the splitting, but since it has no parent, it just makes a parent (a new root node) and inserts into that.

![[Screen Recording 2026-09-30 at 10.50.34 AM.mov.gif|500]]


Now we know all about insertions, what about deletions?

Similar to how we have 3 cases in the binary trees for deletion, there's also 3 cases here.

- First, the easy case: if the value is in a leaf and that leaf has more than the minimum number of values, just delete it.

- Second, what if it already has the minimum key count?

![[Screenshot 2026-10-21 at 1.10.27 AM.jpg|500]]

- What happens is that we borrow from the sibling through the parent.
	1. Find a sibling that has more than the minimum number of values.
	2. Move the parent separator value down into the deficient node.
	3. Move a sibling value up into the parent to replace it:
	    - smallest value from the right sibling, or
	    - largest value from the left sibling.

![[Screen Recording 2026-09-30 at 11.06.16 AM.mov.gif|500]]


- Now there's even a third case, when we remove a value, the node falls below the minimum, and the sibling nodes are at the minimum, then we can't take from the siblings.

![[Screenshot 2026-09-30 at 11.09.26 AM.jpg|500]]

In this case, then we have to merge 2 nodes together!
- We take our value of the no longer valid node, and the separator value between them, and merge them into the sibling node.

![[Screen Recording 2026-09-30 at 11.11.29 AM.mov.gif|500]]



There's another scenario when we are trying to delete a key from the middle of the tree rather than from a leaf.

![[Screenshot 2026-10-21 at 1.12.29 AM.jpg|500]]

It's hard! As that value is also a separator for it's subtrees, we need a new separator that:
- is greater than the values in it's left subtree
- is smaller than the values in it's right subtree

Well, something that feels like binary search tree happens here, we take either the:
- greatest value from it's left subtree
- smallest value from it's right subtree

And fill the gap in.

![[Screen Recording 2026-10-21 at 1.14.55 AM.mov.gif|500]]


Now as we can see, it's possible for the previous case we just saw to occur, where a node has fewer than the minimum number of values allowed inside a node.
- So then, just do case 3 again! Or any other previous case scenarios that we encounter in the process.
