## How does A* Do this?

We start out with a heuristic, say, taking a guess at how far every node is to the final node of the graph.

![[Screenshot 2026-11-09 at 9.59.24 PM.jpg|500]]

In the context of real points on a map, we can estimate how far every node is by computing out the straight line distance between the node and the destination node.

![[Screenshot 2026-11-09 at 10.09.23 PM.jpg|500]]


Now we use that estimate to decide which node to explore next. For each node $n$, we look at two costs.
- $g(n)$ is the cost of the best route we’ve found from the start to $n$.
- $h(n)$ is our estimate of the remaining cost from $n$ to the goal.

We add them to get $f(n) = g(n) + h(n)$, our estimate of the total cost of a route that goes through $n$. 

Dijkstra picks the node with the smallest $g(n)$, and greedy best-first search picks the one with the smallest $h(n)$. A* picks the smallest $f(n)$. A node might look close to the goal, but if we’ve already taken a long detour to reach it, another route may look better overall.

Once we pick a node, we check its outgoing edges just like in Dijkstra. If going through it gives us a shorter route to a neighbor, we update that neighbor’s $g(n)$ and its priority in the queue. On a map with road distances as edge weights and straight-line distance as the heuristic, we’ve found a shortest route when the goal comes out of the queue.

## Pseudo Code Idea


What we keep track of:
- `g[n]` stores the best distance we’ve found so far from the start to node `n`.
- `h[n]` stores the estimated distance from `n` to the goal. This stays fixed during the search. On our distance-weighted map, it’s the straight-line distance to the goal.
- `prev[n]` stores the node we came from on the best route to `n` so far.
- An indexed min-priority queue stores nodes by their priority `f[n] = g[n] + h[n]`. We can update a node’s priority when we find a shorter route to it.

What we do
1. Set `g[start] = 0`, set all other `g` values to infinity, and initialize `prev` to `null` for every node. Insert the start node with priority `h[start]`.
2. Pull the node with the smallest priority from the queue. If it’s the goal, `g[goal]` is the shortest distance. Follow `prev` back to the start and reverse the list to get the path.
3. Otherwise, check each outgoing edge from the current node. Add the edge’s weight to `g[current]` to get the distance from the start to that neighbor through the current node.
4. If that distance improves `g[neighbor]`, update it and set `prev[neighbor] = current`. Insert the neighbor into the queue or update its existing entry using the new priority `g[neighbor] + h[neighbor]`.
5. Go back to step 2. If the queue empties before we pull the goal, the goal is unreachable.
