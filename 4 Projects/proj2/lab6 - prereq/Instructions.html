What you will learn

Build a small command-line program that remembers a story and some dogs across invocations. Practice compiling C++, reading arguments, using the filesystem, and encoding objects into files. The starter includes the same core exercises as the Java lab; persistence and repository methods remain TODOs.

Persistence

Variables exist only while a process runs. C++ static variables do not survive program termination. To remember a dog's age tomorrow, save it to a file today, then load it in a new invocation. A successful implementation must work when every command is launched as a separate process.

Compile and run

From proj2, run:

cd "lab6 - prereq"
make
./build/capers
make check

The no-argument command prints Must have at least one argument. Other commands initially report TODO and exit with status 2. The seven supplied tests will fail until you complete the lab. The compiler builds .cpp files into native code and links an executable; .hpp files declare interfaces and are included by source files.

# Still in lab6 - prereq; keep data separate from your source:
export PATH="$(pwd)/build:$PATH"
mkdir -p playground
cd playground
# These are the target behaviors after you implement the exercises:
capers story "Once upon a time"

argc counts all command-line arguments, including the executable at argv[0]. The supplied main copies argv[1] onward into a vector. Quotes group words into one argument; the shell removes the quotes before passing the argument to your program.

Paths, files, and directories

#include <filesystem>
#include "gitlet/Utils.hpp"
namespace fs = std::filesystem;
fs::path cwd = fs::current_path();
fs::path folder = cwd / ".capers";
// Paths alone do not create anything:
// fs::create_directories(folder);

The current working directory is where you launch the program. A relative path is interpreted from there; an absolute path starts at the filesystem root. Join path components with /. Check with fs::exists, fs::is_directory, and fs::is_regular_file. fs::create_directories also creates missing ancestors.

The shared helpers are declared in ../gitlet/Utils.hpp. Include them as "gitlet/Utils.hpp"; the Makefile sets the include path. readContents returns exact file bytes in a std::string; writeContents creates or overwrites a file. You must create its parent directory first. To append text you may read, concatenate, and rewrite, or use an ofstream opened in append mode. Do not truncate an existing story during setup.

Object encoding

Decide how to represent the dog's name, breed, and age on disk. Reading must reverse writing exactly. Strings can contain spaces, so whitespace splitting is insufficient unless your format handles them. Do not dump the raw bytes of a Dog object: std::string contains memory-management details that are meaningless in another process.

You may use a text format of your own, or the shared BinaryWriter/BinaryReader helpers. These encode strings as a length followed by bytes and unsigned integers as eight bytes in big-endian order. Pick a field order and read it back in that order. The dog's age field is an int; choose an encoding that preserves its value.

If you implement std::string Dog::serialize() const and static Dog Dog::deserialize(const std::string&), the optional writeObject(path, dog) and readObject<Dog>(path) templates become available. Those methods are yours to implement. See the Gitlet serialization guide for the helper contracts.

Exercise: Canine Capers

All saved state belongs under .capers in the current working directory. The recommended layout is:

.capers/
    story
    dogs/
        ...your saved dog files...

Your program creates these directories/files; do not depend on manually creating them first. Assume dog names are unique, as in the original lab. The lab does not require handling invalid input or error cases; Gitlet does.

CommandRequired behavior
story TEXTAppend TEXT plus a newline to the saved story. Print the entire accumulated story.
dog NAME BREED AGECreate and save a dog. Print its toString() result.
birthday NAMELoad that dog, increment its age, print its updated description and birthday greeting, then persist the new age.

Starter responsibilities

  • capers/Main.cpp: argument parsing is partly provided. Finish dog and birthday dispatch. Convert the age with std::stoi.
  • capers/CapersRepository.hpp/.cpp: implement setupPersistence, writeStory, makeDog, and celebrateBirthday; choose the metadata paths.
  • capers/Dog.hpp/.cpp: fields, constructor, toString, and haveBirthday are provided, matching the original starter. Implement fromFile, saveDog, and any encoding methods you choose.

When replacing a stub, remove its NotImplemented throw. The commented-out parameter names in the stubs avoid unused-parameter warnings; restore those names when you use the parameters.

Suggested order

  1. Implement directory/file setup without overwriting existing data.
  2. Implement story and pass the first two tests.
  3. Design the dog's encoding and implement saving/loading.
  4. Wire up dog creation and birthdays.
  5. Run all seven tests, then try names/breeds with spaces and restart the executable between operations.
